# Voyagr-Go — Trip Planner

Plan a trip (destination, days/nights, people, rooms, extra beds), see an editable cost breakdown
(flights, stay, extra bed, cab, breakfast, lunch, dinner, places, activities) with **unit price, per-person
and total**, an **"if N people go"** table, export the itinerary + costs as **PDF**, and save/open trips
as JSON on **Google Drive** (or a local file). **No database** — state lives in the browser; persistence
is a JSON file.

## Stack
Next.js 15 (App Router, TypeScript) for frontend + backend route handlers · Tailwind v4 · Zustand (state) ·
Zod (validation) · `@react-pdf/renderer` (PDF) · Vitest + Testing Library (tests).
TypeScript must stay on **v6** (Next 15 does not support TS 7).

## Commands
- `npm run dev` — dev server · `npm run build` — production build (also type-checks)
- `npm test` — unit tests · `npm run lint` — `tsc --noEmit`
- Copy `.env.example` to `.env.local` for optional integrations.

## Architecture (dependencies point inward: UI -> store/services -> domain)
```
src/domain/        Pure TS, no framework imports. Types, pricing math, categories, schema.
  strategies/      Pricing strategies (quantity per basis) + registry.
src/services/
  pricing/         PriceProvider interface; Estimator, Amadeus, Composite; factory; HTTP client.
  storage/         TripStorage interface; LocalFile + GoogleDrive adapters; serialization.
  export/          ItineraryExporter interface; report view-model; PDF document + exporter.
  container.ts     Composition root — the only place concrete classes are chosen.
src/store/         Zustand store (createTripStore factory + useTripStore singleton).
src/app/           Next.js UI (components/) and the API route (api/prices).
src/data/          destinations.json — offline base rates (INR) + FX table; locations.json — popular places (shown first); airports.json — ~4,000 airports generated by `scripts/build-airports.mjs`.
```

## SOLID and patterns (keep these when changing code)
- **S**: pricing math (`domain/pricing.ts`), providers, storage, export, and UI are separate modules.
- **O**: new pricing basis = `registerStrategy()` in `domain/strategies`; new cost category = an entry in
  `domain/categories.ts`. The calculator is never edited.
- **L/I**: `PriceProvider`, `TripStorage`, `ItineraryExporter` are small; implementations are interchangeable.
- **D**: UI and store depend on interfaces; `services/container.ts` wires implementations.
- **Strategy** (pricing bases), **Factory** (`providerFactory`, `createTripStore`), **Adapter** (Drive/local
  storage), **Facade** (`/api/prices` hides providers and keeps keys server-side), **Composite/fallback**
  (`CompositeProvider`: live first, estimator fills gaps, failures skipped), **Observer** (Zustand subscriptions).

## Domain rules
- Every `CostItem` has `unitPrice`, `basis`, `count`. Quantity comes from the basis:
  perPerson = people · perRoomNight = rooms×nights · perExtraBedNight = extraBeds×nights ·
  perVehicleDay = ceil(people/vehicleCapacity)×days · perPersonDay = people×days ·
  perPersonNight = people×nights · flat = 1. All multiplied by `count`.
- `total = unitPrice × quantity`; `perPerson = total / people`. Money is rounded to 2 decimals.
- Editing a price sets `overridden = true`; provider refreshes (`applyQuotes`) never overwrite overridden items.
- Scenario ("if N go"): rooms = ceil(N / roomOccupancy), extra beds = 0, cabs scale by capacity.
- days/nights stay linked (nights = days − 1) via `withDays` / `withNights`; the itinerary resizes with days.
- PDF uses currency **codes** (not symbols) because built-in PDF fonts lack glyphs such as the rupee sign.

## How to extend
- **New cost category**: add to `CATEGORIES`, the zod enum in `domain/schema.ts`, `CategoryId` in `types.ts`,
  the estimator rates in `destinations.json`, and an icon in `iconNodes.ts` (regenerate from lucide if needed).
- **New price source**: implement `PriceProvider`, add it in `providerFactory.ts` before the estimator.
- **New storage backend**: implement `TripStorage`, register it in `container.ts`.
- **New export format**: implement `ItineraryExporter`; reuse `buildReport()`.

## Prices
The offline estimator (`data/destinations.json`) always works. If `AMADEUS_CLIENT_ID`/`AMADEUS_CLIENT_SECRET`
are set, live flights (origin must be an IATA code) and hotels come from the Amadeus test API and override the estimate.
Prices are approximations; users can edit any of them.

## Google Drive setup
1. Google Cloud Console: create a project, enable **Google Drive API** and **Google Picker API**.
2. Create an **OAuth client ID (Web)**; add `http://localhost:3000` as an authorized JS origin.
3. Create an **API key** (restrict to Picker); note the project number (= app id).
4. Set `NEXT_PUBLIC_GOOGLE_CLIENT_ID`, `NEXT_PUBLIC_GOOGLE_API_KEY`, `NEXT_PUBLIC_GOOGLE_APP_ID` in `.env.local`.
Scope is `drive.file`: the app only sees files it created/opened. Trips are saved to a `Voyagr-Go` folder.
Without a client ID only the local-file option appears.

## Testing conventions
- Tests sit next to the code (`*.test.ts[x]`). Domain and services are tested without React; network is mocked
  via injected `fetch`. Use `createTripStore()` for isolated store tests. New behavior needs a test.

## Cost sections
Each category has a `section` in `domain/categories.ts`: **daily** (stay, extra bed, cab, breakfast, lunch, dinner —
charged per day/night) or **trip** (flights, places, activities — paid once). The UI (`CostTable`) and the PDF
(`report.costSections`) render them separately; the daily section also shows per day and per person per day.

## Itinerary lists and linked costs
A day has `places: PlaceStop[]`. `PlaceStop = { name, people: number|null, fee, activities: ActivityStop[] }` and
`ActivityStop = { name, people: number|null, price }`; activities are children of the place they happen at.
- `fee` / `price` are **per person**. Defaults: place fee 0, activity price 500 (`DEFAULT_ACTIVITY_PRICE`).
- `people: null` means "use the default": a place defaults to everyone on the trip (`config.people`), an activity
  defaults to its place's people. An explicit number overrides it.
- **Costs are derived, not stored.** `domain/itineraryCosts.ts#itineraryItems` turns every place (entry fee) and
  activity into a `CostItem` with `link` set; `summarize()` appends them to the stored items, so adding/removing an
  itinerary row adds/removes its cost line automatically (and the group-size table follows too). Places and
  activities have no default stored items and `addItem` refuses `linked` categories.
- In the Costs tab, linked rows are read-only except the price (`setLinkedPrice` writes back to the itinerary), show a
  lock instead of a delete button, and link to the Itinerary tab. Deleting happens only in the Itinerary.
`ListEditor<T>` is a generic one-item-per-row editor for both levels (native HTML5 drag-and-drop via the grip; Arrow
Up/Down on the focused grip for keyboard users; Enter adds a row). Dragging a place moves its activities with it;
activities only reorder within their place (`moveItem` in `domain/list.ts`). Blank rows are dropped from the PDF.
`domain/schema.ts` migrates older files (string places, day-level or string activities) on open; migrated activities
get price 0 so old totals do not change.

## Places search and dates
- `domain/locations.ts` (`searchLocations`, `findLocation`, `toIata`) backs `LocationCombobox`, the searchable From/To
  dropdown. It matches name, airport name, state/region ("california"), country (also "usa", "uk", "uae"), alternate
  names and airport codes, ignoring accents; a place name beats a code that spells the same (Goa vs GOA/Genoa).
  Arrow keys/Enter/Escape work; free text is allowed via "Use “…”".
- Data: `data/locations.json` is a small curated list of popular places (always available, shown first, and the names
  the offline price estimator knows, e.g. Goa, Kerala). `data/airports.json` (~4,000 scheduled-service airports from the
  public-domain OurAirports dataset) is a **separate chunk loaded lazily** (`loadAllLocations`, `useLocationsReady`)
  and merged in after the curated list; every place gets a unique name (`Chicago · MDW`). Regenerate it with
  `node scripts/build-airports.mjs` (needs network). Tests preload it in `src/test/setup.ts`.
  `origin`/`destination` store the text shown; `toIata()` resolves it for boarding-pass codes and live flights.
- Dates: only `config.startDate` (YYYY-MM-DD or "") is stored. The end date is derived (`endDateOf` = start + nights),
  so "To date", Days and Nights stay in sync: store `setEndDate` sets nights from the range (start is inferred if empty,
  end-before-start is ignored, length capped at 90 nights). Helpers live in `domain/dates.ts` (UTC math, no time zones).
  The date shows on the ticket, per itinerary day, in the PDF, and live-price searches start from it when it is in the future.
